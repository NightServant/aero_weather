# Plan: Locations density (T8) and Settings/FAQ as routes (T6)

Branch `audit/site-fixes`. Both tasks close out the site audit. T7 (bottom tab
bar) was dropped: the navbar now shows links on desktop and collapses them into
a menu below `lg`, and a bottom bar would be a second mobile pattern at the same
level of the hierarchy.

## Global Constraints

- **Next.js 16 App Router.** Per `AGENTS.md`, read the relevant guide under
  `node_modules/next/dist/docs/` before writing routing code. Do not write from
  memory of older Next versions.
- **Tailwind v4.** Arbitrary container queries are `@min-[…]:`, never `@[…]:`,
  which compiles to nothing. `@container` must be on the element being measured.
- **Tests live in `lib/`.** `vitest.config.ts` only includes `lib/**` and
  `test/**`; a test file elsewhere is silently not run. Pure logic goes in
  `lib/` with a sibling `.test.ts`.
- **Time formatting goes through `resolveInstant`** (`lib/format.ts`).
  Open-Meteo returns wall-clock strings with no offset; parsing them as instants
  shifts them by the viewer's offset. Run time-sensitive tests under a non-UTC
  `TZ`.
- **Lint baseline is 18 errors** (pre-existing `react-hooks/set-state-in-effect`
  in `use-prefs`, `use-mobile`, `use-forecast`, `ui/carousel`). Do not add a
  19th: read external state with `useSyncExternalStore` rather than mirroring it
  into state from an effect.
- **`backdrop-blur` is deliberate.** Do not remove it as cleanup.
- **No em dashes** in user-facing copy (DESIGN-SPEC). Plain hyphens.
- Every task ends green on `npx tsc --noEmit`, `npm test`, `npm run lint` at
  baseline, and `npm run build`.

## Task 1 (T8): Locations section density

The Locations section opens with a four-metric summary rail that stacks one
metric per row on phones, so the four take roughly 400px before any city is
visible. The reference app fits six metrics in a third of that.

**Requirements**

1. `components/locations/summary-cards-section.tsx` renders its metrics as a
   two-column grid on small screens, one metric per cell, keeping the existing
   hairline grammar (`border-b` / `md:border-l`, no card fill, no blur). From
   `sm` upward the current layout is unchanged.
2. No horizontal page scroll at 320px, and no cell whose text truncates at
   320px. Verify by measuring `document.documentElement.scrollWidth` against
   `clientWidth`, not by eye.
3. The saved/suggested carousels are unchanged. They are photo-led browsing,
   which is a legitimate use of a carousel.
4. If any pure helper is added (for example deciding which metrics to show when
   a value is missing), it goes in `lib/` with tests covering the empty case,
   the single-location case, and a missing value.

## Task 2 (T6): Settings and FAQ as their own routes

Settings, FAQ, and the weather itself currently share one scroll, so every
session ends in preference controls and help copy the reader did not ask for.

**Requirements**

1. New routes `/settings` and `/faq` under `app/(app)/`, each rendering the
   existing section component unchanged in content, each with its own
   `metadata` (title and description) in the established style.
2. `#settings` is removed from the single-page scroll and from `SECTION_IDS`
   in `lib/sections.ts`. `visibleSectionIds` and `pickActiveSection` must stay
   correct: update `lib/sections.test.ts` so the empty state and the
   bottom-of-page case are still covered with the reduced list.
3. The existing `/settings` redirect stub in `app/(app)/settings/page.tsx` is
   replaced by the real page. Verify no route now redirects to a `#settings`
   anchor that no longer exists.
4. Navbar and footer link to `/settings` and `/faq` as routes, matched on
   `pathname` the way `/privacy` already is, not scroll-spied.
5. `FaqSection` moves off the home page into `/faq`.
6. Nothing may link to an anchor that is not rendered. After the change, load
   `/` and assert every `a[href^="#"]` resolves to an element that exists, in
   both the empty state and with a saved location.
